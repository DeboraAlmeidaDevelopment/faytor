O que é um hash

Uma função de hash transforma qualquer texto em uma sequência de tamanho fixo, chamada hash ou resumo. O mesmo texto sempre gera o mesmo hash. Qualquer mudança, até um espaço ou uma letra maiúscula, gera um resultado completamente diferente. Por isso hashes são usados para conferir a integridade de arquivos, identificar conteúdos repetidos, assinar mensagens e, combinados com outras técnicas, proteger senhas.

O hash não é criptografia: não existe "chave" para voltar ao texto original. O que existe são tabelas de hashes de textos comuns. Por isso o hash de uma senha fraca, como "123456", é encontrado facilmente.

Texto informado ou valor aleatório

Em Texto informado, o hash é calculado enquanto você digita. O texto é convertido em UTF-8 antes do cálculo, o padrão da web e da maioria das linguagens. Por isso, palavras acentuadas como "ação" geram o mesmo hash que você obteria em Python, Node.js ou no comando sha256sum de um arquivo salvo em UTF-8. Atenção a espaços e quebras de linha invisíveis: o comando echo do terminal acrescenta uma quebra de linha no fim, e o hash muda.

Em Valor aleatório, a ferramenta sorteia 32 bytes e mostra esse valor de origem em hexadecimal, para que você possa reproduzir o cálculo. Esse modo é útil para criar identificadores, tokens e massas de dados de teste. A seção Gerar hashes em lote cria até 1.000 hashes de valores aleatórios de uma vez.

HMAC: hash com chave secreta

Com Usar HMAC ativado, o hash é calculado com uma chave secreta (padrão RFC 2104). Só quem conhece a chave consegue gerar o mesmo resultado, por isso o HMAC é usado para assinar webhooks e requisições de API: o servidor recalcula o HMAC do corpo da mensagem e compara com a assinatura recebida. Serviços como GitHub e Stripe assinam webhooks com HMAC-SHA256. O CRC32 não tem versão HMAC.

Formatos de saída e comparação

O resultado pode ser exibido em hexadecimal, com letras minúsculas ou maiúsculas, ou em Base64, que é mais curto (um SHA-256 tem 64 caracteres em hexadecimal e 44 em Base64). Para conferir um download ou uma assinatura, cole o hash esperado em Comparar com um hash. Em hexadecimal, a comparação ignora maiúsculas e minúsculas.

Hash não é a forma certa de guardar senhas

Nunca guarde senhas com MD5, SHA-1 ou mesmo SHA-256 puro. Esses algoritmos foram feitos para serem rápidos, o que permite testar bilhões de senhas por segundo. Para senhas, use algoritmos lentos e com salt, feitos para isso: Argon2id, bcrypt ou scrypt. Para criar senhas de teste, use o Gerador de Senhas.

Privacidade

O cálculo acontece inteiramente no seu navegador: o texto e a chave secreta não são enviados a nenhum servidor nem ficam salvos. Os hashes de valores aleatórios também estão disponíveis como variável no Gerador de JSON, para preencher campos de token e identificador em payloads de teste.
