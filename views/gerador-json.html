O que é o gerador de JSON do Faytor


    
O gerador de JSON monta payloads de API, mocks e massas de dados de teste no formato exato que o seu sistema espera. Você escreve ou cola o modelo, marca os campos que devem variar e escolhe o que cada um representa: CPF, CNPJ, nome, e-mail, celular, senha, número, palavras, Lorem Ipsum e outros. A cada clique, o Faytor preenche o modelo com dados fictícios válidos.


    
Geradores de JSON fake costumam impor uma estrutura pronta e dados em inglês. Aqui, a estrutura é sua, e os dados seguem as regras brasileiras: CPFs e CNPJs com dígitos verificadores corretos, celulares com DDD real do estado escolhido e nomes comuns no Brasil.


    
Como usar, passo a passo


    
    
      
  • Escreva ou cole o modelo no editor. Escolha a indentação acima do editor (2 espaços, 4 espaços ou minificado) e use o botão Formatar JSON para reorganizar o modelo, mantendo as variáveis no lugar. No editor, Tab e Shift+Tab aumentam e diminuem a indentação da linha ou das linhas selecionadas; para sair do editor pelo teclado, pressione Esc e depois Tab.
    • 
      
  • Marque as variáveis. Digite {{nome da variável}} ou posicione o cursor no ponto desejado (ou selecione um valor) e clique em Adicionar variável. O nome é sugerido a partir da chave à esquerda: em "cpf": , a sugestão é cpf.
    • 
      
  • Escolha o tipo e as opções de cada variável na lista abaixo do editor. Nomes como cpf, email ou celular já chegam com o tipo preenchido.
    • 
      
  • Escolha as aspas: aspas duplas, aspas simples ou sem aspas.
    • 
      
  • Clique em Gerar ou em Gerar e Copiar. Para muitos registros, use a seção Gerar JSON em lote.
    • 
    


    
Sintaxe das variáveis


    
As variáveis ficam entre chaves duplas, como {{cpf}}, {{cpf cliente}} ou {{email_2}}. É o mesmo padrão usado pelo Postman, pelo Handlebars e pelo Mustache, e tem uma vantagem importante: {{ nunca aparece em um JSON válido, então não há risco de confundir uma variável com o conteúdo do modelo.


    
    
      
  • O nome pode ter até 40 caracteres: letras (inclusive acentuadas), números, espaço, ponto, hífen e sublinhado.
    • 
      
  • Espaços nas pontas são ignorados: {{ cpf }} e {{cpf}} são a mesma variável.
    • 
      
  • Toda variável reconhecida fica destacada em verde no editor. Se um trecho entre chaves não ficar verde, o nome tem algum caractere não aceito.
    • 
    


    
A mesma variável em vários lugares


    
Dentro de um mesmo JSON, uma variável repete o mesmo valor em todos os lugares onde aparece. No modelo de exemplo, {{nome}} preenche o nome do cliente, o responsável pela empresa e o texto da observação, sempre com a mesma pessoa. Para valores diferentes, use nomes diferentes, como {{cpf 1}} e {{cpf 2}}. Os nomes são únicos: cada nome aparece uma vez na lista de variáveis, com a quantidade de usos ao lado.


    
Aspas: quando usar cada opção


    

      

        
OpçãoModeloResultado

        
          
Aspas duplas"cpf": {{cpf}}"cpf": "123.456.789-09"

          
Aspas simplescpf: {{cpf}}cpf: '123.456.789-09'

          
Sem aspas"cpf": {{cpf}}"cpf": 123.456.789-09

        
      

    


    
Aspas duplas é a opção para JSON. Aspas simples serve para objetos JavaScript e outros formatos que aceitam esse tipo de aspas. Sem aspas insere o valor exatamente como foi gerado, o que é útil para montar outros formatos de texto, como uma linha de CSV ou um comando SQL. Atenção: números com zero à esquerda, como o PIN 0482, não são números JSON válidos.


    
Quando a variável está dentro de um texto entre aspas, como em "observacao": "Cliente {{nome}}", a opção de aspas é ignorada: o valor entra no texto, com os caracteres especiais escapados, e o JSON continua válido.


    
Conferindo o resultado


    
Depois de gerar, o Faytor indica se o resultado é um JSON válido. Se não for, confira as vírgulas e chaves do modelo ou a opção de aspas das variáveis. Aspas simples e valores sem aspas fora de textos produzem resultados que não são JSON, o que pode ser intencional quando o destino é outro formato.


    
Exportar em lote: JSON, JSON Lines ou TXT


    
A seção Gerar JSON em lote cria até 1.000 resultados de uma vez. Cada resultado recebe valores novos, e o formato do arquivo é escolhido ao lado do botão Baixar arquivo:


    
    
      
  • JSON (array): todos os resultados em um único array. É o formato aceito como arquivo de dados pelo Collection Runner do Postman, em que cada objeto vira uma iteração, e pelo mongoimport com a opção --jsonArray.
    • 
      
  • JSON Lines (.jsonl): um objeto compacto por linha, formato padrão do mongoimport e aceito em cargas de dados como o "newline-delimited JSON" do BigQuery.
    • 
      
  • TXT: cada resultado separado por uma linha em branco. Funciona mesmo quando o modelo não é JSON.
    • 
    


    
Os formatos JSON e JSON Lines exigem que cada resultado seja um JSON válido.

Usos comuns


    
    
      
  • Testes de API: gere o corpo de requisições POST e PUT com documentos válidos e cole no Postman, no Insomnia ou em testes automatizados.
    • 
      
  • Mocks e protótipos: monte respostas de API realistas para o front-end avançar antes de o back-end ficar pronto.
    • 
      
  • Massa de dados: exporte centenas de registros em JSON Lines e importe em bancos de homologação.
    • 
      
  • Testes de validação: confirme que o sistema aceita CPF com e sem pontuação, CNPJ alfanumérico e nomes acentuados.
    • 
    


    
Privacidade e limites


    
O modelo e os valores são processados no seu navegador; nada é enviado para servidores. Para você continuar de onde parou, o modelo e as configurações das variáveis ficam salvos no próprio navegador, e limpar os dados do site apaga essas informações. Os valores são fictícios, mas podem coincidir com dados reais. Use-os apenas em ambientes de desenvolvimento e teste.
